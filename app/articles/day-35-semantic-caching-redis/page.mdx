# Day 35 — Semantic Caching with Redis to Cut Token Costs

Semantic caching stores model responses keyed by semantic fingerprints so that semantically-similar prompts reuse a cached response instead of incurring another model call.

## Why it helps

- Cut repeated token costs on similar queries.
- Improve latency for high-volume common queries.
- Provide graceful degradation during provider outages.

## Design considerations

- Choose a fingerprint strategy: truncated embedding hash, nearest-neighbor lookup, or a hybrid with normalized prompts.
- TTLs: short TTLs for dynamic domains, longer TTLs for static knowledge.
- Cache warming for known high-traffic prompts.

## Example implementation

1. Compute an embedding and normalize it (unit length).
2. Use an ANN index to find near fingerprints; if similarity >= threshold, return cached response.
3. Otherwise call model and insert the embedding→response mapping into Redis (cache-aside).

```ts
const key = embeddingHash(embedding);
const hit = await redis.get(key);
if (hit) return JSON.parse(hit);
const resp = await callModel(prompt);
await redis.set(key, JSON.stringify(resp), { EX: ttl });
return resp;
```

## Heuristics

- Use a higher similarity threshold in regulated contexts to avoid incorrect reuse.
- Record cache hits in metrics and monitor hit-rate vs correctness.
