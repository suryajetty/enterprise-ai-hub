# Day 70 — Model Fallbacks and Retry Logic

Provider outages and rate limits are a fact of life. Implement multi-provider strategies, circuit breakers, and deterministic fallbacks to keep services available.

## Strategies

- **Provider pool:** maintain multiple providers with health checks and weighted routing.
- **Circuit breaker:** trip on error-rate or latency and failover to fallback flows.
- **Deterministic fallback:** for some flows, return cached or heuristic-based responses when models are unavailable.

## Example fallback flow

1. Try primary provider with short timeout.
2. On timeout or error, record metrics and route to secondary provider.
3. If all providers fail, return a graceful degraded response and place the request in a retry queue.

## Retry policies

- Use exponential backoff with jitter.
- Rate-limit retries to avoid amplification.
